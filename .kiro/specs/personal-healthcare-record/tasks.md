# 実装計画

## 概要

本実装計画は、SPHR（Simple Personal Healthcare Record）の要件定義書と技術設計書に基づき、TDD（テスト駆動開発）アプローチで段階的に機能を実装します。各タスクは1〜3時間を目安に設定し、テストファースト、リファクタリング、統合の順に進めます。

## 実装タスク

- [x] 1. プロジェクト基盤とインフラストラクチャのセットアップ
- [x] 1.1 プロジェクト初期化と開発環境構築
  - Deno + Hono + TypeScript のプロジェクト構造を作成
  - Docker Compose で app + db コンテナ構成を定義
  - PostgreSQL 15+ の初期化スクリプトとマイグレーション戦略を設定
  - 環境変数管理（DATABASE_URL、PORT、認証情報）を実装
  - _Requirements: 全要件に必要な基盤設定_

- [x] 1.2 データベーススキーマとマイグレーション基盤の構築
  - Drizzle ORM のスキーマ定義とマイグレーションツールを設定
  - users テーブル（ユーザーID、ユーザー名、パスワードハッシュ、作成日時）を作成
  - data_types テーブル（データ種類ID、名前、単位、表示順、有効フラグ）を作成
  - health_data テーブル（データID、ユーザーID、データ種類ID、測定値、測定日、メモ）を作成
  - operation_logs テーブル（ログID、ユーザーID、操作種別、対象データID、操作日時）を作成
  - export_logs テーブル（ログID、ユーザーID、開始日、終了日、形式、出力日時）を作成
  - 外部キー制約、UNIQUE 制約、インデックスを設定
  - _Requirements: 要件1〜7（全機能の基盤となるデータ構造）_

- [x] 1.3 コア共通ユーティリティとエラーハンドリング基盤の実装
  - Result 型（成功/失敗の型安全な結果表現）を実装
  - カスタムエラー型（AuthError、HealthDataError、ValidationError）を定義
  - バリデーションヘルパー（数値検証、日付検証、必須項目チェック）を実装
  - ロギングユーティリティ（構造化ログ、エラーログ、操作ログ）を実装
